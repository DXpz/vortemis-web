Watch the network
without touching it.

Vortemis reads the connection logs your network already produces, scores every flow and flags the anomalies with a MITRE ATT&CK tactic. It never touches your traffic.

Technologies.

Python

Runs the engine end to end: log ingestion, feature extraction, scoring and the API process itself.

PyTorch

Runs the autoencoder that reconstructs each six-feature flow and returns the anomaly probability.

Zeek

Supplies conn.log from the sensor. The engine reads the log, never the packets.

PostgreSQL

Stores every scored flow in a star schema and answers the filters, aggregates and timeline.

MITRE ATT&CK

Provides the tactic vocabulary. Explicit rules label a flow only when it crosses the threshold.

FastAPI

Serves the versioned /v1 contract, the OpenAPI document and the authenticated operator endpoints.

Access

Operators authenticate against the engine. The API returns a bearer access token for fifteen minutes and a refresh token for thirty days; rotation revokes the previous pair.

The OpenAPI document ships as an asset with every release, so a frontend can pin a version and generate its client from it.

FAQ.

Does it inspect payloads?

No. It reads connection metadata only, never packet bodies.

Where does detection run?

Beside your data. The engine reads logs or a capture and writes results to PostgreSQL; it never sits inline.

Is the model calibrated for real traffic?

It ships with a baseline checkpoint and a configurable threshold. Scores are probabilities around the 95th percentile.

Can a frontend use it?

Yes. Everything goes through a versioned /v1 contract with an OpenAPI document published per release.

What happens if the log is truncated or rotated?

The ingestion checkpoint detects it and restarts from the beginning. Deterministic flow ids prevent duplicates.
